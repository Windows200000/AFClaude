# Prompts

Every prompt AFClaude sends lives here, so the dashboard can show and edit them later. These files are the defaults.

| file | used for | placeholders |
|---|---|---|
| `continue.md` | continue message for a resumed AFClaude session: the task-manager at a session-window start or last-stretch slot start (keepalive.py), an approved stalled session in the AFClaude repo (dispatcher.py) | `{reason}`, `{progress}` |
| `fillup.md` | the fill-up run (D-212): continue message for the task-manager shortly before the session reset of a session window whose run stopped early (keepalive.py fillup_pass) | `{reason}`, `{progress}`, `{remaining}`, `{reset}` |
| `session_end_save.md` | the save prompt before a compaction (D-144/D-191, design §5.5): typed into the task-manager near the end of its session window when it will be compacted at the next start (keepalive.py handoff_save_pass), or appended to the fill-up message when a fill-up is planned for that window | `{reset}`, `{session}`, `{tasks}` |
| `compact.md` | the instruction after `/compact` at the start that compacts the task-manager (keepalive.py compact_session); the standing rules are left out of the summary, the SessionStart hook loads them again (D-225) | — |
| `compact_resume.md` | inserted into the continue message after a compaction: the session's latest hand-off from the DB (`handoffs`, rendered by store.render_handoff) | `{handoff}`, `{progress}` |
| `compact_resume_none.md` | the same when there is no hand-off (none saved, or the DB could not be read) | `{why}`, `{progress}` |
| `project_start.md` | first message of a new project session (`--work-on`) | `{title}`, `{desc}`, `{slug}` |
| `continue_foreign.md` | neutral continue message for an approved stalled session that is not an AFClaude session (dispatcher.py; the user's own sessions get only this + `guard_respect.md`, and resume on their own model). (`{context}` is empty since D-205: task sessions and task-managers are never continued at a limit reset, D-204) | `{reason}`, `{context}` |
| `task_start.md` | first message of a task session; unused since D-205 (the dispatcher starts no task sessions, a project's task-manager works its tasks), kept for design phase 3b | `{id}`, `{title}`, `{project}`, `{description}`, `{qa}` |
| `guard_respect.md` | a standing rule: respect the guard hooks even when they're bypassed. Appended to every session message (the user's own sessions: only this), except where the SessionStart hook loads it (below) | — |
| `manager.md` | a standing rule for all but the user's own sessions: act as the project's task-manager and delegate to subagents | — |
| `manager_afclaude.md` | a standing rule after `manager.md`, for sessions working on AFClaude itself: usage report, the clean session stop, GOALS/OPEN_QUESTIONS, public-repo rule, worktrees, budget, D-204/D-219/D-224 | `{session_stop_pct}` (the setting, D-014) |
| `afk_rules.md` | a standing rule after those: the AFK rules for unattended runs (nobody at the keyboard, guards off but respected, no destruction, exceptions in EXCEPTIONS.md, Berlin time); formerly only in the first message | — |
| `session_rules.md` | D-225: the header of each part the repo's SessionStart hook injects (`keepalive.py --session-rules manager` = `manager.md`; `… afclaude` = `manager_afclaude.md` + `guard_respect.md` + `afk_rules.md`) at session start, on resume and after every compaction, for sessions started in the repo root. Two parts: Claude Code caps each hook's context at 10,000 characters | `{part}`, `{what}` |
| `rules_pointer.md` | D-225: replaces the standing rules in session messages to a session started in the repo root (they come from the hook): one line pointing at them. Sessions elsewhere get the four rule files inline instead | — |
| `usage_review.md` | the periodic usage-model review (Opus, medium effort; usage_review.py): one run that tests hypotheses, sorts findings into universal (code, public) vs user-specific (the user model in the DB, `telemetry.py user-model`, local) and leaves an unread-review note in memory. Reused verbatim for a one-off usage review (`usage_review.py --only usage`/`usage,stage-eta`, D-228): same brief, just logged outside the monthly schedule | `{date}`, `{since}` |
| `stage_eta_review.md` | appended to `usage_review.md` in the same monthly run (usage_review.py): the rare stage-ETA review (D-213) that scores the logged stage ETAs (`stage_eta.py --score`) and tunes the stages' session estimates only (D-142 analogue) | `{date}` |
| `stage_eta_review_once.md` | a one-off stage-ETA review outside the monthly schedule (`usage_review.py --only stage-eta`, D-220/D-221), with its own extra brief instead of `stage_eta_review.md` | `{date}` |
| `stage_eta_review_once_after_usage.md` | inserted ahead of `stage_eta_review_once.md` only for the chained one-off (`usage_review.py --only usage,stage-eta`, D-228): points the ETA review at the SEPARATE one-off usage review session's result instead of re-deriving it | `{report}` |
| `usage_haiku.md` | per-session usage classification by Haiku (usage_sampler.py) | `{name}`, `{n}`, `{prompts}`, `{gaps}`, `{totals}` |

Session messages are flattened to one line (tmux send-keys). Literal braces in a file with placeholders must be doubled (`{{ }}`).

**The project docs (dashboard phase 2d part 2, design §7.7).** PROGRESS.md, GOALS.md, EXCEPTIONS.md, ALERTS.md and the review reports are docs in the DB (`project_docs.py`); the DB is the source. `manager_afclaude.md` and the review prompts (`usage_review.md`, `stage_eta_review*.md`) write through the write path (`tasks.py doc append progress "…"`, `tasks.py doc set goals -`, `tasks.py doc set review:<date> -`, MCP `afclaude_doc`), and the AFClaude task-manager runs `tasks.py doc export` (the only file output, D-181) before each commit of the build log. Hand edits of PROGRESS.md / GOALS.md / EXCEPTIONS.md stay valid (the generic prompts, `{progress}`, `afk_rules.md`, `guard_respect.md` still name the files): a scheduled import (every 10 min) merges them into the DB with the runners' notes.
